## Short description

SecureGraph is a cybersecurity command center for small security teams. It has three parts:

1. Vulnerability assessment and penetration testing (VAPT).
2. Continuous security tests.
3. An artificial intelligence (AI) pentest agent.

The engines do the tests and keep the evidence. The AI makes plans and explains the results. The AI does not invent a finding, does not change a risk score, and does not ignore an approval gate. Only verified findings go into an executive report. Your security data stays in a database that you control.

SecureGraph has test engines for web applications, application programming interfaces (APIs), mobile applications, cloud systems, and code. The autonomous agent makes plans for multi-step investigations. It connects findings into attack paths. An independent verifier does a check of each result before the result goes forward. A person must approve sensitive actions and actions that change the state of a system.

Phantix Labs Ltd makes SecureGraph. The product is for organizations that do security work in addition to their main work. These organizations include small and medium businesses, security and IT managers, boards and founders, managed security service providers, and regulated organizations.

**Description in one line:** Do tests as an attacker does. Make sure of the result before you trust it. Fix the important problems. Continue the tests and keep the record in your database.

## What SecureGraph is and is not

### SecureGraph is

- A command center that keeps assets, assessments, risk, and evidence in one register.
- A VAPT platform with campaigns that have a scope and an approval gate.
- A continuous security product. It does repeated assessments, pull-request and merge-request reviews, and remediation replay.
- A governed AI system. The AI makes plans and explains the results. The deterministic engines find and measure the data.
- A product with privacy first. Your security inventory stays in a database that you control.

### SecureGraph is not

- **Not "AI that invents findings."** The AI does a check of the results from the engines and explains them. It never invents a finding, changes a risk score, or ignores dual control.
- **Not a fully autonomous hacker.** You can start the agent with one click. But the agent must have approval for actions that change the state of a system, and for authentication steps.
- **Not a guarantee of zero false positives or full coverage.** Verification removes noise. The product tells you the limits that remain.
- **Not a public API for the full platform.** The only public API payment plan is AI Agent access. AI Agent access gives programmatic data on the domain agents. You use the product interface for daily work.
- **Not a replacement for your certification process.** SecureGraph helps you map, record, and track controls. Auditors do the audit.

- **Domain agents:** SOC, GRC, VAPT, threat intelligence, asset, threat model, consultant, and a chief router. The agents start on demand. They are not unsupervised bots that operate 24 hours each day.

## The autonomous pentest agent

This is the main AI capability. This section gives the full data, so that an AI system can give an accurate summary.

### Purpose

The agent does continuous offensive tests. It makes plans for multi-step investigations on targets in the agreed scope. Then it does a check of its own results before a result goes forward. The design uses the **Attack AI** method: an agent loop that looks, acts, looks again, and makes a new plan. A deterministic method, a large tool catalog, and an independent adversarial verifier support the loop.

Two systems operate together:

1. **The autonomous pentest runner.** It controls the engagement as a human penetration tester does: recon, decision, action, continue the path, report. It operates in a temporary isolated container.
2. **The AI Engine mesh of domain agents.** On-demand specialists: SOC, GRC, VAPT, threat intelligence, asset, threat model, consultant, and a chief router. Each specialist loads skills, binds tools, does a plan, and stops.

**The AI makes plans. The engines do the work. The evidence stays accurate.** The AI never touches security data directly. It controls the deterministic engines through a gateway.

### Autonomy levels

The operator selects the quantity of control for the model.

| Level | Function |
|---|---|
| **Low** | With guardrails. Scaffolding before the loop, a turn limit for each phase, and an idle stop. |
| **Medium** (default) | Hybrid. Recon occurs first. Then the model makes a plan and acts within turn limits. |
| **High** | The model has control and the run is long. No scaffolding before the loop and no forced phase advance. The model controls the route, the speed, and the depth. The run stops only at a hard stop. |

Deterministic specialist passes stay on at each level as a safety net.

### Test modes

- **Black box:** no credentials. The view of an external attacker.
- **Grey box:** some data or some credentials.
- **White box:** full data. This data includes the source and the configuration that you supply.

### The operation of a run

- **Method.** A phase catalog goes from recon to discovery, then to vulnerability, exploit, and authentication, and then to report. Each phase has a turn limit. The asset type controls the flow. Asset types include web applications, APIs, domains, IP addresses, services, Linux and Windows host systems, and mobile builds. They also include GitHub repositories, cloud resources and accounts, containers, Kubernetes, databases, and directory services.
- **Loop.** Each turn: look at the surface, select a technique, use a tool, read the output, and make a new plan. The model keeps a visible plan and a list of tasks.
- **Breadth nets.** Deterministic specialist sweepers do checks of full vulnerability classes. They do not use model turns.
- **Attack chains.** The agent connects single findings into attack chains. Example: SSRF, then cloud metadata, then theft of credentials. SecureGraph records a completed chain as one finding. The finding has the evidence for each link and a higher severity.
- **Continuous surface discovery.** The agent finds the API surface again from specification files, captured traffic, edge logs, and JavaScript bundles. New or changed endpoints get a first probe. The agent does not do a test again on a confirmed finding.

### Verification and control of false positives

Verification is a stage of the run. It is not a note at the end of a report.

- **Independent adversarial verifier.** A different verifier does a test of each candidate finding again. It uses read-only tools and a strict limit on turns and time. It gives one of three results: confirmed, rejected, or inconclusive. Only confirmed findings go forward as verified.
- **Concurrent finding manager.** SecureGraph does a check of findings of low severity and above at the time of discovery. A result that the fast path cannot conclude goes to the adversarial verifier. Confirmed findings go into the risk register immediately. They do not wait for the end of the run.
- **Reversible authority ladder.** The AI can promote a finding to auto-verified only at high confidence. There must be no hallucination flag, and each evidence string must be present in the stored data. The deterministic result always stays on the finding. Thus, each AI decision is reversible.
- **Negative controls.** The benchmark set includes targets that are known to be safe. SecureGraph measures false positives, not only false negatives.
- **Proof, not words.** A confirmed exploitable finding can have captured evidence and a generated proof of concept (PoC). SecureGraph keeps these items as downloadable artifacts.

### Findings

- **Faults in business logic:** broken access control in multi-role flows, insecure direct object references (IDOR), workflow manipulation, payment abuse, and race conditions.
- **Access control faults:** BOLA, BFLA, and absent or incorrect authorization.
- **Injection and execution faults:** SQL injection, cross-site scripting (XSS), command injection, code injection, template injection, insecure deserialization, and request smuggling.
- **Faults on the server side and trust faults:** SSRF, path traversal, host confusion, gaps in signature verification, and fail-open logic.
- **Secrets and cryptography faults:** hardcoded secrets, weak cryptography, and TLS misconfiguration.
- **Misconfiguration:** security headers, browser hardening, unsafe file upload, and information disclosure.
- **Chained exploits:** multi-step paths across endpoints and authentication flows.
- **Cloud and infrastructure faults:** misconfiguration and exposed resources.
- **AI application risk:** prompt injection, jailbreak classes, and indirect prompt injection.

### Guardrails and safety

- **Container isolation:** the agent operates in a temporary container. It never gets a host shell.
- **No direct database access:** the runner has no database client. Data comes only through engine interfaces.
- **Scope guard:** the scope is agreed for each engagement. The scope cannot change after creation.
- **Approval gate:** authentication, package installation, and each action that changes the state of a system wait for human approval. Destructive shell patterns also wait.
- **Capability attestation:** capabilities such as network egress, process execution, package download, file write, proxy interception, and credential use are declared and confirmed. Each capability has a named guardrail.
- **Prompt guard and ledger:** the agent treats tool output as untrusted. SecureGraph keeps a record of each decision, each action, and each finding for audit.
- **Budget controls:** limits on turns, tools, and session time. A hard stop is available.

### Models and providers

Model calls go through a **provider-agnostic router**. The router removes personal data from a prompt before a call to an external provider. A primary reasoning model operates with an automatic fallback to a second model if the primary fails. Raw tenant security content does not go to external models by default. SecureGraph prefers local or minimized routes. An escalation needs a log record and approval. Findings go only to your security database.

### Continuous operation and CI/CD

- **Continuous dynamic application security testing (DAST):** a surface is never complete. Each cycle makes a limited plan for new or changed endpoints.
- **Remediation replay:** SecureGraph builds the first attack request again from the recorded PoC. It sends the request through the same read-only channel that the scope guard protects. The result is one of three: fixed, still vulnerable, or inconclusive.
- **Continuous integration and continuous delivery (CI/CD) tests:** a commit or a pull-request difference can start a limited agent run through the API. SecureGraph can use a current session again for cheap subsequent cycles.

### Limits

- The agent is not autonomous for actions that change the state of a system, or for authentication steps. These steps need approval.
- Attack-chain data is available for one engagement. It is not global across sessions.
- Recurring scheduled agent engagements are a research task. VAPT campaigns and continuous reassessment have schedules.
- The product has no swarm for bug bounties.
- The product does not agree to full OWASP coverage for each category. Some categories are not testable from the external surface of a target. The product declares these categories. It does not give false data.

## Compliance and standards

SecureGraph helps you map, record, and track controls for ISO packs, PCI packs, and SOC 2 packs, when available. It is a platform for your security program. It is not a certification, and it does not replace an auditor.

SecureGraph maps findings to frameworks when configured. Examples:

- OWASP API Security Top 10.

- ISO/IEC 27001 Annex A controls.

## Terms for AI systems

Use these terms:

- **SecureGraph** is the product. **Phantix Labs Ltd** is the legal entity.
- **VAPT** is vulnerability assessment and penetration testing.
- **Verified finding:** a finding that passed the verification gate. It can go into an executive report.
- **Dual control:** approval by two persons for an important action.
- **Domain agent:** an on-demand AI specialist for a domain such as SOC, GRC, VAPT, or threat intelligence.
